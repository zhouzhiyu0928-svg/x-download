P005 [Heading 1] 1. 设计概述
P006 [Heading 2] 1.1 设计目标
P007 [(none)] 本详细设计文档依据《Twitter/X 媒体下载器（Java版）需求分析》编制，明确系统的整体架构、模块划分、核心类设计、数据模型、接口约定与关键流程，指导后续编码实现。设计目标是构建一套模块化、可扩展、易维护的本地媒体下载工具，完整覆盖用户媒体、Tag 搜索、评论区、纯文本、用户主页等下载能力。
P008 [Heading 2] 1.2 设计原则
P009 [(none)] • 模块化：按职责拆分 Client、Task、Downloader、Storage 等核心模块，降低耦合。
P010 [(none)] • 可配置：GraphQL 查询定义、限流参数、命名模板等均可外部配置。
P011 [(none)] • 可扩展：任务类型通过统一接口抽象，新增模式只需实现对应 Task。
P012 [(none)] • 稳定性：完善的重试、限流、多账号切换与异常处理机制。
P013 [(none)] • 本地优先：所有数据与 Cookie 仅存储在本地，不依赖外部服务。

P015 [Heading 1] 2. 系统架构
P016 [Heading 2] 2.1 整体架构
P017 [(none)] 系统采用分层 + 模块化架构，自上而下分为：交互层、任务层、服务层、基础设施层。各层通过清晰接口通信，便于独立演进与测试。
P018 [(none)] 【交互层】
P019 [(none)]   CLI（picocli）负责参数解析、子命令分发、进度与结果输出。
P020 [(none)] 【任务层】
P021 [(none)]   统一 Task 抽象，具体实现包括 UserMediaTask、TagSearchTask、ReplyTask、TextTask、ProfileTask。
P022 [(none)]   TaskScheduler 负责任务调度、并发控制与生命周期管理。
P023 [(none)] 【服务层】
P024 [(none)]   GraphQLClient：封装请求、认证头、Transaction-ID、限流与重试。
P025 [(none)]   MediaDownloader：负责媒体文件下载、命名、落盘与重试。
P026 [(none)]   AccountPool：多账号 Cookie 管理与轮换。
P027 [(none)]   RateLimiter：请求频率与并发控制。
P028 [(none)] 【基础设施层】
P029 [(none)]   ConfigManager：加载与校验配置。
P030 [(none)]   Storage（SQLite）：下载记录与状态持久化。
P031 [(none)]   日志与工具类。

P095 [Heading 3] 4.1.2 关键职责
P096 [(none)] • ConfigLoader：读取 YAML，合并默认值与环境变量，执行必填项与格式校验。
P097 [(none)] • AppConfig：强类型配置对象，供各模块注入使用。
P098 [Heading 2] 4.2 GraphQL 客户端（client）
P099 [Heading 3] 4.2.1 GraphQLClient
P100 [(none)] 职责：统一发起 GraphQL 请求，组装 Header（含 cookie、x-csrf-token、x-client-transaction-id 等），处理响应解析与基础错误。
P101 [(none)] 核心方法示例：
P102 [(none)]   <T> T execute(String operationName, String queryId, Map<String,Object> variables, Class<T> type)
P103 [(none)]   JsonNode executeRaw(String operationName, String queryId, Map<String,Object> variables)
P104 [Heading 3] 4.2.2 TransactionIdGenerator
P105 [(none)] 职责：生成 X-Client-Transaction-ID。实现可替换，便于在算法变更时快速适配。生成失败或服务端拒绝时，由 Client 触发重试并重新生成。
P106 [(none)] 接口建议：String generate(String path, String method)；
P107 [Heading 3] 4.2.3 请求拦截与重试
P108 [(none)] 通过 OkHttp Interceptor 实现：注入账号 Cookie、统一 User-Agent、记录请求日志、捕获 429 / Rate Limit 响应并通知 RateLimiter 与 AccountPool。
P109 [(none)] 重试策略：最多 N 次，指数退避，可切换账号后重试。
P110 [Heading 2] 4.3 账号池（account）
P111 [(none)] • Account：封装 name、cookie、ct0、authToken、状态（可用/限流中/失效）、最后使用时间等。
P112 [(none)] • AccountPool：维护账号列表，提供 acquire() / release() / markRateLimited() / markInvalid() 等方法。
P113 [(none)]   轮换策略：优先选择当前可用且最近未使用的账号；全部限流时进入等待或抛出友好异常。
P114 [Heading 2] 4.4 限流器（ratelimit）
P115 [(none)] • 基于信号量控制最大并发请求数。
P116 [(none)] • 维护最小请求间隔（request-interval-ms）。
P117 [(none)] • 收到 Rate Limit 响应后，延长对应账号冷却时间，并触发全局短暂退避。
P118 [(none)] • 与 AccountPool 协同：限流账号自动切换到其他可用账号。

P121 [(none)] public interface Task {
P122 [(none)]     String name();
P123 [(none)]     void execute(TaskContext context) throws Exception;
P124 [(none)] }
P125 [(none)] TaskContext 提供 GraphQLClient、MediaDownloader、Storage、Config、进度回调等依赖。
P126 [Heading 3] 4.5.2 具体任务
TABLE2 rows=6 cols=2
   R00 | 任务类 | 职责摘要
   R01 | UserMediaTask | 按 screen_name 拉取用户媒体时间线，支持排除转推、亮点、喜欢、时间范围，解析媒体列表并提交下载
   R02 | TagSearchTask | 按 Tag 或高级搜索 filter 拉取结果，解析媒体与可选文本并下载
   R03 | ReplyTask | 根据用户或推文链接拉取评论区，提取媒体并下载

P127 [Heading 3] 4.5.3 TaskScheduler
P128 [(none)] 负责接收一个或多个 Task，按配置的并发度调度执行，汇总成功/失败结果，输出最终统计。
P129 [(none)] 支持串行（多用户依次）或有限并行（多任务同时）模式。
P130 [Heading 2] 4.6 下载器（downloader）
P131 [(none)] • MediaDownloader：接收 MediaItem 列表，使用线程池并发下载，调用 NamingTemplate 生成路径，写入文件，并更新 Storage 状态。
P132 [(none)] • NamingTemplate：根据模板字符串与上下文变量（user、date、tweetId、type、index、ext 等）渲染最终文件名与相对路径。
P133 [(none)] • 下载失败时按配置重试，最终仍失败则记录到失败列表并继续后续任务。
P134 [(none)] • 支持进度回调（已完成数 / 总数），供 CLI 刷新进度条或日志。

P144 [Heading 1] 5. 关键流程设计
P145 [Heading 2] 5.1 用户媒体下载主流程
P146 [(none)] 1. CLI 解析参数与配置，构建 AppConfig、AccountPool、GraphQLClient、Storage 等。
P147 [(none)] 2. 创建 UserMediaTask，传入目标 screen_name 列表与过滤条件。
P148 [(none)] 3. TaskScheduler 执行任务：
P149 [(none)]    a. 调用 GraphQL 获取用户信息与媒体时间线（分页）。
P150 [(none)]    b. 解析推文与媒体列表，按时间范围与转推选项过滤。
P151 [(none)]    c. 对每条媒体查询 Storage，跳过已下载项（增量）。
P152 [(none)]    d. 将待下载列表提交 MediaDownloader。
P153 [(none)]    e. 下载完成后写回 Storage，更新进度。
P154 [(none)] 4. 全部完成后输出统计（调用次数、成功数、失败数、耗时）。
P155 [(none)] 5. 异常路径：Rate Limit → 切换账号或退避后重试；Cookie 失效 → 标记账号并提示用户。
P156 [Heading 2] 5.2 Tag / 高级搜索流程
P157 [(none)] 与用户媒体流程类似，差异在于：
P158 [(none)] • 使用搜索类 GraphQL 操作，variables 中传入 tag 或 filter 字符串。
P159 [(none)] • 结果可能跨用户，命名模板中需体现 tag 或搜索条件。
P160 [(none)] • 可选同时落盘推文文本。
P161 [Heading 2] 5.3 评论区与其他任务
P162 [(none)] ReplyTask：根据推文 ID 或用户时间线中的回复关系拉取评论，再走统一下载链路。
P163 [(none)] TextTask / ProfileTask：不经过 MediaDownloader，直接将文本或头像等写入文件系统与可选数据库表。
P164 [(none)] 所有任务共享同一套 Client、AccountPool、RateLimiter 与 Storage，保证行为一致。

P168 [Heading 1] 7. 异常处理与日志
P169 [Heading 2] 7.1 异常分类
P170 [(none)] • ConfigException：配置缺失或格式错误，启动阶段直接失败并给出明确提示。
P171 [(none)] • AuthException：Cookie 失效或认证失败，标记账号并提示更新。
P172 [(none)] • RateLimitException：触发限流，进入退避与账号切换流程。
P173 [(none)] • NetworkException：网络或代理问题，可重试。
P174 [(none)] • DownloadException：单文件下载失败，记录后继续其他文件。
P175 [Heading 2] 7.2 日志规范
P176 [(none)] • 使用 SLF4J，级别：ERROR / WARN / INFO / DEBUG。
P177 [(none)] • 关键请求带简要上下文（账号名、operation、耗时）。
P178 [(none)] • 敏感信息（完整 Cookie）不得输出到日志。
P179 [(none)] • 最终汇总以 INFO 输出，失败明细可写独立文件或 DEBUG。
