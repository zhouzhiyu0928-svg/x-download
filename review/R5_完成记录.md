## 本轮发现并修掉的 Bug

1. **写入异步导致的「读回旧值」**：`TargetRepository.updateCheck/setEnabled` 走的是异步写队列但没 `flush()`，
   校验完立刻读列表仍是「未校验」。已补 `flush()`（测试从 4 红转绿）。
2. **账号调用计数在批量记账时漂移**：`QuotaLedger.recordCalls(account, n)` 只让账号 +1（`Account.recordCall` 单次递增），
   与账本/界面显示不一致 → 新增 `Account.recordCalls(now, n)` 按次数累加。
3. **接口异常无兜底**：请求体不是合法 JSON 时处理器抛异常，HttpServer 只回**空体 500**，页面一片空白无从排查。
   已加统一 `guarded()` 包装：畸形 JSON → 400 + 可读原因，内部异常 → 500 + 异常名与消息。
4. **`\R` 转义写错**（Java 无 `\R` 转义）：请求体多行文本的切分规则改为 `[\r\n]+`。
5. 已有 ID 重复加入时**备注被丢弃** → 现在带新备注就更新。
6. 批量汇总的 **API 调用数恒为 0** → `TargetListTask.Summary` 现在累计 `apiCallCount` 并反映到界面。

## 口径说明（与旧行为的变化）

- **每日调用上限默认取消**：`config.example.yaml` 与线上 `config.yaml` 均已改为 `per-account-daily: 0`。
  想恢复限制就把该值设成正数（界面「设置」页会显示当前值与含义）。
  注意：**频率限流仍在**（`rate-limit.request-interval-ms` / `max-concurrent`），取消的是每日调用**总量**上限。
- 校验与下载都是真实请求，两者串行（操作台同一时刻只跑一个任务）。
- 无效 ID 会被批量下载**跳过**（不阻断其它 ID），但会一直留在列表里提醒你删除。
