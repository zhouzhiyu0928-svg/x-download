### 关于 TxId（值得记下的结论）

实测确认：`UserByScreenName` 与 `UserMedia` 这两个端点**不需要 `x-client-transaction-id`**，
只要 `user-agent` + `authorization: Bearer <公开 bearer>` + `cookie` + `x-csrf-token`（取自 ct0）+ `referer` 即可。
故本阶段无需引入 TxId 生成器（原 Python 版同样只在 reply/tag 里用）。

## 真机联调抓出的 5 个真 bug（都已修 + 有测试兜住）

1. **同页水位线自噬（最严重）**：把「本轮见到的最新 ID」当成「初始水位线」用 → 处理完同页第一条推文后，
   同页更老的推文全被判为「已处理」跳过。**实测一页 4 条推文只下到 1 条、丢 11 张图**。
   修法：`initialWatermark`（判定用）与 `maxSeenId`（回写用）彻底拆开；`UserMediaTaskTest` 专门守这条。
2. **无限翻页烧配额**：数据取完后服务端仍回「空页 + 游标」，被当成「还有下一页」→ 一次运行烧掉 200 次调用（110 秒）。
   修法：整页无推文即到底 + 游标去重 + 单用户最大页数兜底（300）。
3. **`./downloads` 被清成 `_\downloads`**：`PathSanitizer` 把 `.` 段当成「尾巴是点」清成了 `_`，文件落到错目录。
   修法：保留 `.` 与 `..` 段；已补回归用例。
4. **dry-run 污染状态**：dry-run 也回写水位线 → 只「列过没下过」的推文被记成已处理，后续增量全部跳过。
   修法：dry-run 一律不写水位线/记录，并打日志说明。
5. **水位线提前终止缺失**：即使全部推文都 ≤ 水位线，仍会多翻一页。
   修法：整页最新 ID ≤ 水位线即终止（省配额），已由集成测试断言 `apiCallCount <= 2`。

另有 3 个**测试代码自身**的问题（不是产品 bug，但会掩盖真问题）：MockWebServer 大量请求时只能用常驻
`Dispatcher`（`enqueue` 队列空会阻塞，曾让单用例跑 83 秒）；`ObjectNode.set()` 链式调用返回 `JsonNode` 需拆开写；
下载器测试必须关连接池再 `shutdown()`。
