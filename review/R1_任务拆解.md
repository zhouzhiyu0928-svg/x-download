# X 媒体下载器 · R1 任务拆解（迭代 1 / 共 4）

> 依据：《需求分析》V1.1 §6.1、《详细设计》V1.1 §9（第一阶段）、评审意见与整改台账（H1–H6 / S1–S14 / P1–P7 / Q1–Q6）
> 工程根：`D:\x down`（与 `doc/`、`review/` 同级）

## 迭代划分（对齐文档阶段）

| 迭代 | 对应文档阶段 | 内容 | 出口条件 |
|---|---|---|---|
| **R1** | 阶段一（纯逻辑内核） | 工程骨架 + 领域模型 + 配置 + 存储（WAL/单写队列/水位线/配额账本）+ 命名与清洗 + CLI 骨架 + `--dry-run` | `mvn test` 全绿 + `--dry-run` 能跑通 + fat-jar 产出 |
| **R2** | 阶段一（网络层） | GraphQLClient（完整请求头表 + TxId 按需生成 + 有限重试 + Lease 归还）、operations 外部配置、操作失效识别、AccountPool 轮换、RateLimiter + 配额闸 | 单测全绿；`--dry-run` 显示配额估算；真机联调留用户 |
| **R3** | 阶段一（任务与下载） | UserMediaTask（水位线增量）、MediaDownloader（`.part` + Range + 原子改名）、TaskScheduler、进度回调、结果单写队列接入 | 真机跑通一个用户的媒体下载 + 增量二次运行零重复 |
| **R4** | 阶段二 | TagSearchTask / ReplyTask / TextTask / ProfileTask、accountBinding 完善、统计报告（CSV/MD）、打包与使用文档 | 全类型可用 + 交付文档 |

## R1 任务清单

| # | 任务 | 交付物 | 验收 |
|---|---|---|---|
| R1-1 | 工程骨架 | `pom.xml`（Java 17 / picocli / okhttp / jackson / snakeyaml / sqlite-jdbc / slf4j+logback / junit5 / shade fat-jar）、`tools/mvn.sh`（本机 mvn 坏的，走 java -cp plexus）、`.gitignore`、`NOTICE`（MIT 署名，Q5） | `bash tools/mvn.sh test` 成功；`package` 出 `target/x-media-downloader.jar` |
| R1-2 | 领域模型 | `User` / `Tweet` / `MediaItem`（含 `mediaKey`、`variantBitrate`）/ `DownloadRecord` / `TaskResult` / `DownloadSummary` + 枚举 `MediaType` / `RecordStatus` / `TaskType` / `AccountStatus` | 单元测试 + 记录字段与《数据库结构说明》V1.1 一致（H5/S6） |
| R1-3 | 命名与清洗（P2/S9） | `util.PathSanitizer`（盘符/UNC 先剥、非法字符替换、保留名、限长）、`util.NamingTemplate`（稳定键默认模板、未知变量启动即失败） | 崩溃现场路径回归 + 盘符后无冒号 + 相对路径 `a:b` 不误判盘符（真实 bug 回归） |
| R1-4 | 配置模块（S2/H2/H6） | `config.AppConfig`（含 `dbPath`/`log`/`quota`/`proxy.mode`/`accounts[].note`）、`ConfigLoader`（YAML + 环境变量 + CLI 优先级、必填与格式校验、友好报错）、`config.example.yaml` | 优先级/缺项/坏模板/坏时间范围 各有断言；错误信息可读（F19） |
| R1-5 | 存储模块（H1/H3/H5/S3/S4/S5/S6/S7/S8） | `storage.Database`（WAL + busy_timeout + 单写队列）、`DownloadRecordRepository`（仅 `SUCCESS` 参与去重、UPSERT 覆盖失败、`clearByMode` 三档）、`SyncCursorRepository`（水位线）、`QuotaLedgerRepository`（账号×日 账本） | 建表后 `information_schema` 式对象普查（表/索引/唯一键）；UPSERT 重试覆盖断言；水位线读写断言；WAL 生效断言 |
| R1-6 | 配额与限流（H2/S12） | `ratelimit.QuotaLedger`（预算估算、耗尽抛 `QuotaExhaustedException`）、`ratelimit.RateLimiter`（信号量 + 最小间隔 + 退避）、异常体系 | 启动前估算断言（推文数 ÷ 19）；配额耗尽后不再重试；`Lease` 归还对称（无泄漏） |
| R1-7 | 命令行骨架（P6/Q1） | `cli.MainCommand` + `cli.AppBootstrap`（依赖装配集中）、`--dry-run`（只校验配置 + 估算配额 + 打开数据库，不发起任何请求）、`ExitCodes` | `java -jar … --dry-run -c config.yaml` 输出估算与校验结果，退出码正确；无网络调用（可用断网/无 Cookie 证明） |
| R1-8 | 测试与验证 | JUnit 5 套件（`mvn test`）+ `tools/verify-r1.sh` 落包与产物断言 | 套件全绿；落包断言（jar 内有类、SQLite 驱动版本、`Main-Class`） |

## 本迭代**不含**（明确排除，避免范围蔓延）

- 任何对 X 的真实网络请求（GraphQL / 下载）—— R2/R3
- Tag / 评论区 / 纯文本 / 主页任务 —— R4
- 统计报告 CSV/MD —— R4
- 图形化操作台 —— Q1=B，不在本期
- 代理池实现（配置结构留 `mode: single|pool`，本迭代只用 `single`）—— Q6
- 视频多码率选择只在模型层留字段 —— R3 实现

## 关键配置键（R1 落定，后续迭代不得改动语义）

```
save-path / db-path
log.level / log.file / log.max-history
accounts[].name / accounts[].note / accounts[].cookie
proxy.mode(single|pool) / proxy.list[]
download.max-concurrent / has-video / has-retweet / has-highlights / likes
download.time-range / naming-template / enable-incremental / video-variant / resume-enabled
rate-limit.request-interval-ms / max-retries
quota.per-account-daily / reserve-for-retry / estimate-tweets-per-call
```

环境变量覆盖前缀 `XMEDIA_`，优先级：**CLI 参数 ＞ 环境变量 ＞ 配置文件 ＞ 内置默认值**。

## 验收方式（用户侧）

1. `bash tools/mvn.sh test` → 全绿
2. `java -jar target/x-media-downloader.jar --dry-run -c config.yaml` → 打印配置校验结果与配额估算
3. 真实采集联调在 R2/R3 交付时由用户执行（需要有效 Cookie 与代理）
